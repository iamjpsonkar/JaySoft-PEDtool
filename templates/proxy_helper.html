Proxy Server & API Mocker

A lightweight proxy that sits between your client and a real API. You can mock any endpoint to return custom responses, or let unmatched requests pass through to the real API.

How It Works

Your Client
→
Proxy Server
→
Mock exists? Return mock
→
No mock? Forward to real API

Quick Start

  1. Register a proxy with your API's base URL
  2. Create mocks for the endpoints you want to simulate
  3. Point your client to /proxy/<identifier>/ instead of the real API

Core Endpoints

  • POST /proxy/create/ — Register a new proxy
  • POST /proxy/mock/create/ — Create or update a mock
  • GET /proxy/get/<id>/ — View proxy config & mocks
  • ANY /proxy/<id>/<path> — Proxy or mock a request

Management Endpoints

  • DELETE /proxy/delete/<identifier>/ — Delete a proxy and all its mocks
  • GET /proxy/list/ — List all proxies with mock counts
  • POST /proxy/clone/ — Clone a proxy
  • POST /proxy/mock/delete/ — Delete a specific mock
  • POST /proxy/sequence/reset/ — Reset sequence counters

Import / Export

  • GET /proxy/export/<identifier>/ — Export proxy + mocks as JSON
  • GET /proxy/export/all/ — Export all proxies
  • POST /proxy/import/ — Import proxies from JSON

History & Monitoring

  • GET /proxy/history/<identifier>/ — Get request history
  • POST /proxy/history/<identifier>/clear/ — Clear request history
  • GET /proxy/ratelimit/<identifier>/ — Get rate limit status
  • GET /health — Health check

State & Storage

  • State API (CRUD) — Read, write, merge, clear per-proxy state
  • _store (Write) — Write to state from mock responses
  • dbget (Read) — Read state values in responses
  • Staging Pattern — Generate ID, store data, return in response
  • Recipes — Login, wallet, orders, gift cards

Advanced Features

  • Dynamic Placeholders Reference
  • URL Pattern Matching
  • Response Delay
  • Custom Status Codes
  • Mock Sequencing
  • Mock Conditionals
  • Rate Limiting
  • Request History

State API

Each proxy has a state — a JSON object stored in SQLite. Use it to make mocks remember data between requests (wallets, orders, tokens, etc.).

ActionMethodURLBody

curl -X PUT '/proxy/state/myproxy/' \
  -H 'Content-Type: application/json' \
  -d '{"wallet": {"bonus": 2000}, "orders": {}, "tokens": {}}'

_store — Writing to State

Add a _store key to any mock response. It runs as a side-effect before the response body is resolved, then gets removed from the response.

Operation shapes

ShapeExampleEffect
Set by path{"path": "a.b.c", "value": "hello"}state.a.b.c = "hello"
Set by collection+key{"collection": "orders", "key": "ORD1", "value": {...}}state.orders.ORD1 = {...}
Delete{"path": "tokens.alice", "delete": true}Removes state.tokens.alice

Single operation

{
  "_store": {"path": "counter", "value": 42},
  "message": "stored"
}

Multiple operations

{
  "_store": [
    {"path": "user.name", "value": "jsonget(name)"},
    {"path": "user.lastLogin", "value": "now()"}
  ],
  "result": "ok"
}

Dynamic paths & values

Both path and value support all resolvers:

{
  "_store": [
    {"path": "orders.jsonget(orderId).status", "value": "CREATED"},
    {"path": "orders.jsonget(orderId).amount", "value": "jsonget(amount)"},
    {"path": "wallet.bonus", "value": "snippet(max(0, dbget('wallet.bonus', 0) - jsonget('amount', 0)))"}
  ]
}
Execution order: _store runs and commits to DB before the response body is resolved. This means dbget() in the body always sees what _store just wrote.

dbget — Reading from State

Standalone resolver (in response values)

{
  "balance": "dbget(wallet.bonus, 0)",
  "name": "dbget(user.name, anonymous)"
}
No quotes around args in standalone dbget(). Default is always returned as a string.

Inside snippet() (for types & arithmetic)

{
  "balance": "snippet(dbget('wallet.bonus', 0))",
  "enough": "snippet(dbget('wallet.bonus', 0) >= jsonget('amount', 0))",
  "total": "snippet(dbget('wallet.bonus', 0) + dbget('wallet.rcs', 0))"
}
Inside snippet(), use Python quotes around string args. Types are preserved (int, bool, etc.).

When to use which

NeedSyntax
Simple string read"dbget(user.name, guest)"
Numeric value"snippet(dbget('balance', 0))"
Arithmetic"snippet(dbget('balance', 0) - jsonget('amount', 0))"
Comparison"snippet(dbget('balance', 0) >= 100)"

Staging Pattern (lastId)

The most important pattern for stateful mocks. Use it when you need to generate a random ID, store data under it, and return it in the response.

Problem

alnum() generates a different value each time. You can't use the same alnum() in both path and response.

Solution: stage then reference

{
  "_store": [
    {"path": "lastOrderId", "value": "alnum(8,4)"},
    {"path": "orders.dbget(lastOrderId).status", "value": "CREATED"},
    {"path": "orders.dbget(lastOrderId).amount", "value": "jsonget(amount)"}
  ],
  "orderId": "snippet(dbget('lastOrderId'))",
  "status": "CREATED"
}

How it works:

  1. Op 1: alnum(8,4) generates e.g. "AbCdEfGh1234", stored at state.lastOrderId
  2. Op 2: dbget(lastOrderId) resolves to "AbCdEfGh1234" — path becomes orders.AbCdEfGh1234.status
  3. After _store commits, body resolves: snippet(dbget('lastOrderId')) reads back "AbCdEfGh1234"
Path template rule: In _store paths, do NOT use quotes around resolver args: dbget(lastOrderId) not dbget('lastOrderId'). Quotes become part of the key name.
In snippet() expressions, do use quotes (Python syntax): dbget('lastOrderId', '').

Nested body fields (dotted args workaround)

Path templates split on . naively. jsonget(giftcard.cardNumber) in a path breaks. Stage it first:

"_store": [
  {"path": "lastCard", "value": "snippet(str(jsonget('giftcard.cardNumber')))"},
  {"path": "cards.dbget(lastCard).redeemed", "value": true}
]

Storage Recipes

Login with token storage

Seed: PUT /proxy/state/myproxy/ {"tokens": {}}

{
  "conditions": [],
  "responses": [{
    "when": [
      {"field": "username", "operator": "exists", "source": "json"},
      {"field": "password", "operator": "exists", "source": "json"}
    ],
    "then": {
      "_store": [
        {"path": "tokens.jsonget(username).accessToken", "value": "alnum(16,16)"},
        {"path": "tokens.jsonget(username).refreshToken", "value": "alnum(16,16)"}
      ],
      "body": {
        "accessToken": "snippet(dbget('tokens.' + jsonget('username') + '.accessToken'))",
        "refreshToken": "snippet(dbget('tokens.' + jsonget('username') + '.refreshToken'))",
        "expiresIn": 3600
      },
      "status_code": 200
    }
  }],
  "default": {"body": {"error": "Missing credentials"}, "status_code": 400}
}

Wallet balance (deduct on payment)

Seed: PUT /proxy/state/myproxy/ {"wallet": {"bonus": 2000}}

// Read balance:
{"balance": "snippet(dbget('wallet.bonus', 0))"}

// Deduct:
{
  "_store": [
    {"path": "wallet.bonus", "value": "snippet(max(0, dbget('wallet.bonus', 0) - jsonget('amount', 0)))"}
  ],
  "newBalance": "snippet(dbget('wallet.bonus', 0))"
}

// Add back (refund):
{
  "_store": [
    {"path": "wallet.bonus", "value": "snippet(dbget('wallet.bonus', 0) + jsonget('amount', 0))"}
  ],
  "newBalance": "snippet(dbget('wallet.bonus', 0))"
}

Create + Lookup (order system)

Seed: PUT /proxy/state/myproxy/ {"orders": {}}

// Create order (POST):
{
  "_store": [
    {"path": "lastOrderId", "value": "alnum(8,4)"},
    {"path": "orders.dbget(lastOrderId).amount", "value": "jsonget(amount, 0)"},
    {"path": "orders.dbget(lastOrderId).status", "value": "CREATED"}
  ],
  "orderId": "snippet(dbget('lastOrderId'))"
}

// Lookup order (POST) — 200 if found, 404 if not:
{
  "conditions": [],
  "responses": [{
    "when": [{"source": "snippet",
      "value": "dbget('orders.' + jsonget('orderId', '__NO__'), '__NO__') != '__NO__'"}],
    "then": {
      "orderId": "jsonget(orderId)",
      "amount": "snippet(dbget('orders.' + jsonget('orderId') + '.amount', 0))",
      "status": "snippet(dbget('orders.' + jsonget('orderId') + '.status', 'UNKNOWN'))"
    }
  }],
  "default": {"body": {"error": "Order not found"}, "status_code": 404}
}

Token refresh with rotation

Key: Stage the username before rotating, so the body can find it after tokens change.

{
  "conditions": [],
  "responses": [{
    "when": [{"source": "snippet", "value": "valid_refresh_token(jsonget('refreshToken', ''))"}],
    "then": {
      "_store": [
        {"path": "lastRefreshUser", "value": "snippet(str(refresh_token_user(jsonget('refreshToken'))))"},
        {"path": "tokens.dbget(lastRefreshUser).accessToken", "value": "alnum(16,16)"},
        {"path": "tokens.dbget(lastRefreshUser).refreshToken", "value": "alnum(16,16)"}
      ],
      "body": {
        "accessToken": "snippet(dbget('tokens.' + dbget('lastRefreshUser', '') + '.accessToken'))",
        "refreshToken": "snippet(dbget('tokens.' + dbget('lastRefreshUser', '') + '.refreshToken'))"
      },
      "status_code": 200
    }
  }],
  "default": {"body": {"error": "Invalid refresh token"}, "status_code": 401}
}

Double-redeem prevention

Seed: PUT /proxy/state/myproxy/ {"giftcards": {}, "wallet": {"bonus": 2000}}

{
  "conditions": [],
  "responses": [
    {
      "when": [{"source": "snippet",
        "value": "dbget('giftcards.' + str(jsonget('cardNumber', '__NONE__')) + '.redeemed', False) == True"}],
      "then": {"body": {"error": "Card already redeemed"}, "status_code": 400}
    },
    {
      "when": [{"field": "cardNumber", "operator": "exists", "source": "json"}],
      "then": {
        "_store": [
          {"path": "lastCard", "value": "snippet(str(jsonget('cardNumber')))"},
          {"path": "giftcards.dbget(lastCard).redeemed", "value": true},
          {"path": "wallet.bonus", "value": "snippet(dbget('wallet.bonus', 0) + 500)"}
        ],
        "body": {"amount": 500, "message": "Redeemed"}, "status_code": 200
      }
    }
  ],
  "default": {"body": {"error": "Invalid card"}, "status_code": 400}
}

Dynamic Placeholders

Use these in mock response values. They are resolved at request time.

PlaceholderDescriptionExample ValueOutput
headerget(Name) Value of request header headerget(Authorization) Bearer xyz...
jsonget(key) Value from JSON request body jsonget(user_id) 12345
paramget(name) Value of query parameter paramget(page) 2
pathparamget(prefix) URL segment after prefix pathparamget(orders) 789 (from /orders/789/...)
upper(n) Random uppercase letters upper(6) KFMXQP
lower(n) Random lowercase letters lower(8) xqrtmnbl
chars(n) Random mixed-case letters chars(5) kBmQz
digit(n) Random digits digit(4) 8294
alnum([x,y,...]) Alternating letters + digits alnum([3,2,4,1]) aBc12dEfG3
dbget(path, default) Read from proxy state dbget(wallet.bonus, 0) 2000
now() ISO 8601 UTC timestamp now() or now(+3600) 2026-04-29T12:00:00Z
now_epoch() Unix epoch (seconds) now_epoch() 1777593600.0
snippet(expr) Evaluate safe Python expression snippet(dbget('balance',0) + 100) 2100
snippet() runs in a sandboxed evaluator. Available builtins: abs, int, float, str, len, min, max, round, sum, sorted, list, dict, bool, range.
Available context functions: jsonget(), dbget(), headerget(), paramget(), now(), now_epoch(), upper(), lower(), digit(), alnum(), valid_token(), refresh_token_user(), verify_password(), bearer_token().

URL Pattern Matching

When creating mocks, you can use several endpoint formats:

FormatExampleMatches
Exact path /users/123 Only /users/123
Dynamic segment /users/<id>/orders /users/456/orders, /users/abc/orders
Full URL https://api.example.com/users/123 When the constructed URL matches exactly

Resolution order: exact path → path with leading / → full URL → pattern match. First match wins.

pathparamget with indexed prefix

If a URL has the same prefix repeated (e.g. /api/items/1/items/2), use pathparamget(items_2) to get the second occurrence.

Response Delay

Simulate network latency by adding a _delay_ms field to your mock response. The proxy will wait the specified number of milliseconds before returning the response.

Example Mock

{
  "proxy_identifier": "payments-v2",
  "end_point": "/orders/<id>/status",
  "method": "GET",
  "mock": {
    "_delay_ms": 2000,
    "order_id": "pathparamget(orders)",
    "status": "processing"
  }
}
Note: The _delay_ms field is consumed by the proxy and will not appear in the response body. The delay is applied before the response is sent to the client.
Request arrives
→
Mock matched
→
Wait _delay_ms
→
Return response

Custom Status Codes

By default, mocks return HTTP 200. To return a different status code or custom headers, use the structured response format with status_code, body, and headers.

Example Mock

{
  "proxy_identifier": "payments-v2",
  "end_point": "/orders",
  "method": "POST",
  "mock": {
    "status_code": 201,
    "body": {
      "order_id": "digit(8)",
      "message": "Order created successfully"
    },
    "headers": {
      "X-Request-Id": "alnum([4,4,4,4])",
      "Location": "/orders/12345"
    }
  }
}
FieldTypeDescription
status_codeintegerHTTP status code to return (e.g. 201, 400, 404, 500)
bodyobjectThe actual response body sent to the client
headersobjectAdditional response headers to include
Note: If the mock is a plain object without status_code, body, and headers keys, the entire object is returned as the body with status 200.

Mock Sequencing

Define a list of responses instead of a single object. Each successive call to the endpoint returns the next response in the list. After the last response, it cycles back to the first.

Example Mock

{
  "proxy_identifier": "payments-v2",
  "end_point": "/orders/<id>/status",
  "method": "GET",
  "mock": [
    { "status": "pending",    "progress": 0   },
    { "status": "processing", "progress": 50  },
    { "status": "completed",  "progress": 100 }
  ]
}
Call 1
→
{"status": "pending"}
→
Call 2
→
{"status": "processing"}
→
Call 3
→
{"status": "completed"}

Call 4 cycles back to {"status": "pending"} and so on.

Tip: Use POST /proxy/sequence/reset/ to reset the counter back to the first response at any time.

Mock Conditionals

Return different responses based on request properties. Define conditions that check values from the JSON body, headers, or query parameters, and match them using operators.

Structure

{
  "proxy_identifier": "payments-v2",
  "end_point": "/orders",
  "method": "POST",
  "mock": {
    "conditions": true,
    "responses": [
      {
        "when": [
          { "source": "json", "key": "amount", "operator": "gt", "value": 1000 }
        ],
        "then": {
          "status_code": 400,
          "body": { "error": "Amount exceeds limit" }
        }
      },
      {
        "when": [
          { "source": "header", "key": "X-Priority", "operator": "eq", "value": "high" },
          { "source": "json", "key": "currency", "operator": "eq", "value": "USD" }
        ],
        "then": {
          "order_id": "digit(8)",
          "priority": "high",
          "currency": "USD"
        }
      },
      {
        "when": [
          { "source": "param", "key": "dry_run", "operator": "exists" }
        ],
        "then": {
          "message": "Dry run - no order created"
        }
      }
    ],
    "default": {
      "order_id": "digit(8)",
      "status": "created"
    }
  }
}
Note: Conditions within a single when array are combined with AND logic. The first matching responses entry wins. If none match, the default response is used.

Rate Limiting

The proxy supports per-proxy rate limiting to simulate API throttling. When a proxy exceeds the configured request limit within the time window, subsequent requests receive a 429 Too Many Requests response.

Configuration

Rate limiting is configured via environment variables:

VariableDefaultDescription
PED_RATE_LIMIT_MAX100Maximum requests allowed per window
PED_RATE_LIMIT_WINDOW60Time window in seconds

429 Response

{
