Proxy Server & API Mocker

A lightweight proxy that sits between your client and a real API. You can mock any endpoint to return custom responses, or let unmatched requests pass through to the real API.

How It Works

Your Client
→
Proxy Server
→
Mock exists? Return mock
→
No mock? Forward to real API

Quick Start

  1. Register a proxy with your API's base URL
  2. Create mocks for the endpoints you want to simulate
  3. Point your client to /proxy/<identifier>/ instead of the real API

Endpoints

  • POST /proxy/create/ — Register a new proxy
  • POST /proxy/mock/create/ — Create or update a mock
  • GET /proxy/get/<id>/ — View proxy config & mocks
  • ANY /proxy/<id>/<path> — Proxy or mock a request
  • Dynamic Placeholders Reference
  • URL Pattern Matching
▶ POST /proxy/create/

Register a new proxy server instance.

FieldTypeRequiredDescription
api_domainstringYesBase URL of the real API
identifierstringNoCustom ID (auto-generated if omitted)

Request

{
  "api_domain": "https://api.example.com",
  "identifier": "payments-v2"
}

Response

{
  "identifier": "payments-v2",
  "message": "api mocker created successfully",
  "old_mocks": null
}

cURL

curl -X POST http://localhost:8000/proxy/create/ \
  -H 'Content-Type: application/json' \
  -d '{"api_domain": "https://api.example.com", "identifier": "payments-v2"}'
▶ POST /proxy/mock/create/

Create or update a mock response for a specific endpoint and HTTP method.

FieldTypeRequiredDescription
proxy_identifierstringYesThe proxy to attach this mock to
end_pointstringYesPath or URL to mock (supports patterns)
methodstringYesGET, POST, PUT, PATCH, or DELETE
mockobjectYesResponse JSON (supports placeholders)

Request

{
  "proxy_identifier": "payments-v2",
  "end_point": "/orders/<id>/status",
  "method": "GET",
  "mock": {
    "order_id": "pathparamget(orders)",
    "status": "confirmed",
    "tracking": "upper(8)",
    "amount": "jsonget(total)"
  }
}

Response

{
  "proxy_identifier": "payments-v2",
  "end_point": "/orders/<id>/status",
  "method": "GET",
  "new_mock": { ... },
  "old_mock": null
}
▶ GET /proxy/get/<identifier>/

Retrieve the configuration and all mocks for a proxy.

cURL

curl http://localhost:8000/proxy/get/payments-v2/

Response

{
  "api_domain": "https://api.example.com",
  "mocked_requests": {
    "/orders/<id>/status": {
      "GET": {
        "order_id": "pathparamget(orders)",
        "status": "confirmed"
      }
    }
  }
}
▶ ANY /proxy/<identifier>/<endpoint>

The main proxy endpoint. Supports GET, POST, PUT, PATCH, DELETE.

Request hits proxy
→
Check mocks (exact → prefixed → pattern)
→
Match found: return mock with placeholders resolved
No match
→
Forward to api_domain + endpoint
→
Return real API response

Example

# If mock exists for /orders/123/status GET, returns mock.
# Otherwise forwards to https://api.example.com/orders/123/status
curl http://localhost:8000/proxy/payments-v2/orders/123/status

Dynamic Placeholders

Use these in mock response values. They are resolved at request time.

PlaceholderDescriptionExample ValueOutput
headerget(Name) Value of request header headerget(Authorization) Bearer xyz...
jsonget(key) Value from JSON request body jsonget(user_id) 12345
paramget(name) Value of query parameter paramget(page) 2
pathparamget(prefix) URL segment after prefix pathparamget(orders) 789 (from /orders/789/...)
upper(n) Random uppercase letters upper(6) KFMXQP
lower(n) Random lowercase letters lower(8) xqrtmnbl
chars(n) Random mixed-case letters chars(5) kBmQz
digit(n) Random digits digit(4) 8294
alnum([x,y,...]) Alternating letters + digits alnum([3,2,4,1]) aBc12dEfG3
snippet(expr) Evaluate safe Python expression snippet(len("hello")) 5
snippet() runs in a sandboxed evaluator. Only safe builtins are available (abs, int, str, len, min, max, sorted, range, etc.). No imports, file I/O, or exec allowed.

URL Pattern Matching

When creating mocks, you can use several endpoint formats:

FormatExampleMatches
Exact path /users/123 Only /users/123
Dynamic segment /users/<id>/orders /users/456/orders, /users/abc/orders
Full URL https://api.example.com/users/123 When the constructed URL matches exactly

Resolution order: exact path → path with leading / → full URL → pattern match. First match wins.

pathparamget with indexed prefix

If a URL has the same prefix repeated (e.g. /api/items/1/items/2), use pathparamget(items_2) to get the second occurrence.
